# Contributing

Thanks for wanting to help. This list stays useful because people notice things: a new dashboard worth listing, a stale link, a product that shut down. Here is how to pitch in.

## Three ways to help

- **Suggest a dashboard.** Open an issue with the suggestion form and give us the product name, the URL and the category.
- **Add an entry yourself.** Open a pull request that adds one line to `README.md`.
- **Report a problem.** If a link is dead, a product has shut down, or a description is wrong, open an issue with the report form.

## The entry format

Every entry is one line:

```
- [Name](url) - Description.
```

The description:

- is objective: what the product does, plus what sets it apart from similar entries;
- runs 6 to 16 words;
- starts with a capital letter and ends with a period;
- never uses marketing words such as `seamless`, `powerful`, `robust`, `ultimate`, `delightful` or `leverage`;
- never uses an em dash or en dash;
- never repeats the product name.

## Where it goes

Place your entry in the right category, in A to Z order by name. The sponsor's entry stays first in its category regardless of alphabetical order; only the maintainers edit that entry.

## The quality bar

This is a selective list, not a directory of every dashboard that exists. Before an entry gets added, it needs to clear all of these:

- it is a real dashboard product, not a tutorial, article or one-off demo;
- it works today;
- it has been updated in the last year;
- someone could honestly recommend it.

Entries that fail any of these get turned down, even if the product is popular elsewhere.

## Disclose your affiliation

If you work on the product, or you are the one who made it, say so in the pull request or issue. Submitting your own product is welcome. Just tell us up front.

## AI-assisted contributions

Using AI to help draft a suggestion or a description is fine, as long as a person has checked every claim against the live product first. A description copied from marketing copy or generated without verification will be rejected.

## What gets rejected

- duplicate entries;
- unmaintained or shut-down products;
- descriptions written like marketing copy;
- pull requests that bundle more than one entry.

## One entry per pull request

Keep each pull request to a single addition, edit or removal. It is easier to review and easier to revert if something turns out to be wrong.

## The website

Many entries also have a longer write-up on [awesome-dashboards.com](https://awesome-dashboards.com). The maintainers write those outside this repo. If one gets a fact wrong, open an issue with the report form and link the page.

## About the sponsor

DashSuey sponsors this list and is made by the same people who maintain it. That does not change which other products get listed or how they are described. The bar above applies the same way to every entry.

## Code of conduct

Everyone taking part in this project, in issues, pull requests or discussion, is expected to follow our [code of conduct](.github/CODE_OF_CONDUCT.md).
